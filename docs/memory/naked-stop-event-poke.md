**The gap:** the broker's stop-coverage audit (which re-attaches/flattens naked positions) runs once per **30s** reconcile cycle (`RECONCILE_INTERVAL_SECONDS=30`). Naked detection is NOT event-driven for the mid-life orphaned-stop case — the immediate-reconcile poke (`reconcile.py:751 request_immediate_reconcile`) exists but its ONLY caller (`main.py:1033`) fires on bracket-child FILLS, not on a stop CANCELLED while the position is still held. So a held position whose stop is orphaned/cancelled is unprotected up to ~30s (and fresh failed-bracket entries up to ~60-90s via the `find_naked_positions` grace_seconds=60). Live: `BROKER_STOP_COVERAGE_FLATTEN_ON_NAKED=true`, `FLATTEN_CONFIRM_CYCLES=2`. Native IBKR trail protects in real-time ONCE placed; exposure is only the no-live-stop window.

**BUILT + DEPLOYED DARK 2026-06-22 (main HEAD 3d7d0bfe, broker restarted HEALTHY, flag `BROKER_STOP_COVERAGE_POKE_ENABLED=False` — INERT/no .env override).** `OrderRegistry` got a TTL self-cancel registry (`note_self_cancel`/`was_self_cancel`, consume-once+prune, defensive lazy-init); `cancel()` auto-tags; `StopManager.cancel_stop` (exit-race) tags its coid via injected callback; `main._should_poke_naked_stop()` (pure, 8 tests) decides; the gated poke is in the OrderCancelledV3 handler. Code live but poke does nothing until armed. **TO ARM (NOT yet): shadow-observe window first** (log "would-poke" — currently it logs `naked-stop poke:` + fires only when flag on), then `BROKER_STOP_COVERAGE_POKE_ENABLED=true` in .env + broker restart. The 30s poll is the unchanged backstop.

**The fix (scoped — now BUILT, see above):** poke `request_immediate_reconcile()` on `OrderCancelledV3`/statusEvent='Cancelled' for a protective coid (`_stp`/`_tp`/reattach-trail) whose key is still HELD and which the broker did NOT itself cancel → ~1s detection. **Safety spine:** the poke changes only WHEN the audit runs, never WHAT — places/cancels nothing; `_wakeup` coalesces a burst into one cycle; the loop is single+serialized (`reconcile.py:3556-3590`) so no concurrent/duplicate audit; worst case of a bad poke = one extra harmless reconcile. The audit's EXISTING guards own correctness: `select_excess_stops_to_cancel` (de-dup double-stops, never under-cover), `find_orphan_stops` (held set from IBKR-TRUTH positions not the DB → can't fire into a flat book → no spurious short), caps (MAX_REATTACH=20). Faster detection STRICTLY REDUCES the spurious-short / [[orphan-stop-optimistic-cancel]] / [[estx50-fesx-short-tangle]] risk.

**Only delicate part:** the broker-initiated-vs-external cancel filter (tag the broker's own protective-stop cancels in a TTL set; suppress the poke for those). Correctness does NOT depend on it (a miss = one extra reconcile); it's for noise/storm avoidance. 30s poll STAYS as backstop; feature-flag `BROKER_STOP_COVERAGE_POKE_ENABLED` default OFF. Out-of-scope follow-up: the 60s fresh-grace (failed-entry-bracket) wants a separate fast post-entry stop-landing verify. Full test matrix in the doc.
