The profit-ratchet's "hit profit then disappeared/went negative" defect (operator-reported 2026-06-18) is a **restart-only seed bug**, NOT a firing/execution bug.

**Diagnosis (evidence-backed):** steady-state tracking is correct — the in-memory max/min fold works, and a 25-min clean-watch window caught the ratchet arming + banking live (M6E short armed +$13.8 → banked on the 25% give-back). The "why sometimes not others" is mostly **the arm floor**: positions that peak ≥ floor arm and bank; positions that peak < floor never arm (by design) and ride the 20-min FLAT_CLOCK to a loss — the $10 floor (`PROFIT_RATCHET_ACTIVATION_FLOOR_USD`, was effectively ~$90 via 0.15%) pulls far more into arming range. The one real code bug: on a **strategy restart**, `running_extreme` re-seeded near entry (`load_futures_peak` returns None on opened_at mismatch → falls back to `avg_cost`), discarding the pre-restart peak — proven live: MNQ true-high +$109 but seeded peak +$7 → protected nothing.

**Fix:** on first-sight, fold the TRUE intra-hold extreme from banked `bar_history` H/L over [opened_at, now] into the seed (peak HIGH long / trough LOW short), keyed by **contract_key uppercased** (m6e→M6E, dax_micro→DAX_MICRO, estx50_mc→ESTX50_MC — the live-price series; DAX/ESTX50/MGC are dead feeds). New helper `load_bar_extreme` in `futures_peak_state.py`; wired into `futures_runner.py` seed block. Persisted peak + entry remain fallbacks; most-favourable wins. Tests: `tests/test_futures_bar_seed.py` (10 pass), zero new failures vs baseline.
