G-Lab — Report Generator Rewrite

Scope, 19 August 2026 · replacing the LLM-driven Friday report with deterministic Python

0. The finding that changes the order of work

122 of 169 analysis scripts read only capture.db — a rolling window of a few trading days — and none of them say so. They print "last 400d" or "full history" while scanning a fraction. This is not a reporting bug; it is a correctness bug in the research layer, and it silently invalidates any conclusion drawn over a period longer than the hot tier.

Three instances were found and fixed on 18–19 August: the run census, the walk-forward harness, and (after the census was fixed) the fix itself, which reintroduced the same hardcoded timeframe one file away. Two of the remaining 122 — abs_veto_robustness.py and adaptive_exit_bt.py — are invoked by the Friday report's own shadow section.

Therefore: the data-access layer is prerequisite work, not part of the rewrite. Rewriting the report generator on top of 122 scripts that each narrow their own dataset would produce a deterministic report that is confidently wrong — which is worse than an LLM-written one that is occasionally vague.

2. Prerequisite — the data-access layer (do this first)

2.1 One reader, and it cannot silently narrow

gazbot7.lake.connect() # already exists: V5 archive + Parquet lake + hot SQLite │ ▼ glab.data.bars(symbol, tf=None, since=None, until=None) │ · tf=None -> choose the WIDEST-SPAN timeframe fine enough for the caller's need │ · records what it scanned: source tier, timeframe, row count, span, gaps │ · RAISES if the requested window exceeds what is held, never truncates ▼ every report component, every backtest, every study
Two rules learned the hard way, both non-obvious.
(a) Choose timeframe by COVERAGE, not by fineness. Preferring the finest bar picks 5-second data — which exists only for the weeks we captured ourselves — and discards nine months of backfilled minute bars to gain a resolution the measurement does not use. Selection must be widest-span among timeframes fine enough to resolve the question, with anything coarser refused rather than accepted.
(b) A label that misnames its source is worse than no label. The walk-forward printed "alphabot.db 1m" while reading the lake, because it echoed a default instead of what it used. Every component must emit the tier, timeframe, row count and span it actually scanned.

4. Greenfield — the honest exception

The seven gf_* phases invoke zero Python scripts. They are wholly "here is a data contract, go find something". Three separable parts:

PartAutomatable?
Running a hypothesis sweep across a parameter surfaceYes — this is already what the backtest engine does
Applying the validation battery (leave-one-out, both-halves, placebo, neighbourhood)Yes — deterministic, and partly built
Choosing which hypothesis space is worth searching, and recognising an artefactNo
Recommendation: do not remove it — make it optional and structured. Greenfield stays LLM-driven behind a provider interface, and is required to emit structured output (candidate, mechanism, evidence, sample size, refutation condition) rather than prose. Then gf_report becomes templating, and a customer without an AI key still gets a complete instrument that MEASURES — just not one that PROPOSES.

6. What this buys, commercially

  • No LLM dependency in the core. A customer needs no AI key to get capture, storage, backtesting, census, walk-forward, validation and a full weekly report.
  • Removes an operational liability. Session-based model credentials once silently no-opped the router for 10.5 hours. Shipping that dependency to customers is not viable; here it becomes an optional add-on rather than a single point of failure.
  • Reproducibility. A deterministic report run twice on the same data produces the same bytes. That is auditable in a way an LLM-written one is not — and it is what a professional buyer will ask for first.
  • Cost. The per-run cost of the weekly report goes to approximately zero.
  • Honest positioning. "Deterministic research instrument, optional AI analyst" is a stronger and more defensible claim than either "AI-powered" or "no AI".
The one thing not to promise. Hypothesis generation is the least automated link in the loop and the most tempting to overstate. The deterministic product measures, validates and reports. It does not invent the next question — and a scope that claims otherwise will be found out.
